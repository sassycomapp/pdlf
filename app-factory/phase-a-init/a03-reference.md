# Step 3 — New application with context: Reference

What the orchestrator does at Step 3, in order. Agent-facing. Fixed values: [[[pdlf:app-factory/phase-a-init/a03-config|Step 3 Configuration]]](C:/pdlf/app-factory/phase-a-init/a03-config.md). It is carried out at item 8 of [[[pdlf:app-factory/phase-a-init/a01-reference|Step 1 Reference]]](C:/pdlf/app-factory/phase-a-init/a01-reference.md), after the choice of entry; that reference then completes the entry: the slug checks, the business row, the entry row, the receipt and the stop.

1. Ask David for the business's name and the mode, `full` or `test`.
2. List the folders of the business folder. Ask David which apps already exist, and confirm each against its folder `{slug}-app{n}`.
3. Ask whether the business's existing project library holds its context. If it does, the context is `{slug}-project-context`: note whether it is already in `C:\dev\dev-{slug}\{slug}-project-context\` or still in `{slug}-project-library\`, where Step 11 moves it with David's permission.
4. Search GBrain for the context's documents, naming the source `{slug}-project-context` when it is registered and `{slug}-project-library` otherwise. List the documents found for David to confirm, so that the context Step 12 reads is named, not guessed.
5. Ask whether the application follows a reference platform (for `mb-4-ecom`, Medusa). If it does: record its name and where its material is kept now; Step 11 places it in the project library's `reference-platform-local\`.
6. Return to item 9 of [[[pdlf:app-factory/phase-a-init/a01-reference|Step 1 Reference]]](C:/pdlf/app-factory/phase-a-init/a01-reference.md).
